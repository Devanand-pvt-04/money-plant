# Money Plant

Money Plant is a personal finance app for Deva and friends. It keeps one accurate, cloud-synced ledger and fills it mostly from bank SMS. The Android MVP comes first; iOS follows later.

- Product requirements: `docs/PRD.md`. Requirement IDs such as CAP-1 and LED-3 are defined there. Cite them in commits and PRs.
- Architecture: `docs/architecture.md`
- Decisions: `docs/decisions/`

## Stack

- pnpm monorepo, TypeScript everywhere except the native modules
- `apps/mobile`: React Native with Expo SDK 58 (development builds, not Expo Go), Expo Router (`src/app/`), expo-sqlite with SQLCipher, Drizzle, supabase-js
- `apps/mobile/modules/sms-reader`: Kotlin Expo module (SMS receiver, notification listener)
- `packages/core`, `parser`, `matcher`, `categoriser`, `db-schema`: shared logic, no React imports
- `supabase/`: Postgres migrations with row-level security, edge functions (Deno, TypeScript)
- `services/cas-parser`: Python service wrapping casparser
- AI: a self-hosted open model (Ollama) on Deva's PC. Edge functions queue AI jobs in Postgres and a worker on the PC runs them; nothing calls a model directly. Built in milestone 6 (decision 0006).

## Rules

- Money is always an integer in the smallest unit of its currency (paise for INR; `_paise` columns hold minor units of the row's currency, decision 0017). Never use floating point for amounts or exchange rates. Never assume ₹: format with the amount's currency.
- Every transaction's postings sum to zero in each currency (double-entry). Write balances only as sums of postings, never as stored totals.
- Every transaction has at least one source row. No entry exists without a source.
- Raw SMS text never leaves the device. Don't log it, sync it or put it in an AI job. Only parsed fields leave the parser.
- Secrets (AI worker token, SMTP, MSG91) live only in Supabase edge function secrets. Never put them in the app or the repo.
- Every new table needs `updated_at`, `deleted_at` and a client-generated UUID primary key, plus row-level security policies and a case in `supabase/tests/database/rls.test.sql` proving another user can't read or change it. See `docs/security.md`.
- Free tiers only. Don't add a paid service without asking.
- Capture is never limited to a fixed list of banks: any business sender's money SMS reaches the general reader (decision 0017). ICICI, HDFC, HSBC and SBI had tuned rules first; PNB followed from a friend's samples. Adding a bank's tuned rules needs anonymised fixtures in `packages/parser/fixtures/<bank>/`.
- Never add code that moves money. UPI links only hand off to the user's own UPI app.

## Commands

- `pnpm install`: install the workspace (pnpm 12, Node 22)
- `pnpm typecheck` and `pnpm test`: run both before every PR; CI runs the same commands
- `npx supabase db start` then `npx supabase test db`: database access tests (needs Docker); CI runs them with `supabase db advisors`, `pnpm audit` and gitleaks
- `cd apps/mobile && npx expo install <pkg>`: add Expo or React Native packages so versions match the SDK. Use `pnpm --filter <pkg> add` for everything else
- `cd apps/mobile && npx expo run:android`: local development build (needs Android Studio), or `npx eas-cli@latest build --profile development --platform android` for a cloud build
- `cd apps/mobile && npx eas-cli@latest build --profile production --platform android`: the production APK Deva uses daily. JS fixes ship to preview by themselves after a merge to main (`.github/workflows/ota-update.yml`), then to production from Actions → OTA update once tried (decision 0011). By hand: `npx eas-cli@latest update --channel preview --platform android`
- Migrations reach the hosted project through `.github/workflows/migrate.yml`: after a merge to main that touches `supabase/migrations`, and before every OTA update from the Actions tab. By hand: `npx supabase db push` (after `npx supabase link --project-ref dywcmxixmzeqhzifuhwm`)
- `npx supabase functions deploy <name>`: deploy one edge function from `supabase/functions/` (for example `delete-account`)

## Expo notes

- Expo changes between SDK releases. Before writing code against an Expo or React Native API, read the versioned docs (https://docs.expo.dev/llms.txt) instead of relying on memory.
- A change that needs a new native build (a native package or a config plugin) must bump `version` in `app.json`, so over-the-air updates never reach a build without that native code.
- `android/` and `ios/` are generated by prebuild. Never edit them; configure native behaviour in `app.json` and config plugins.
- SQLCipher doesn't exist in Expo Go. The app warns in development and refuses to open the database in release builds without it.
